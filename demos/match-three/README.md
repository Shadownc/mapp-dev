# 糖果连线

一个可接入 Linux Do / Discourse 微应用的 8×8 三消游戏，共 7 关。点击两个相邻糖果交换，连成三个或更多后消除；在每关的步数限制内收集完指定颜色的糖果即可过关。

包含棋盘入场、选中轻摆、交换与无效交换回弹、消除粒子、逐轮掉落补齐、浮动加分、连击提示和胜利彩纸。动画期间锁定棋盘输入，仍可暂停或重玩本关；系统或社区开启“减少动效”时直接展示结果。每种目标颜色显示已收集数量，手机上可滑动交换糖果。

## 七关挑战

社区排行榜已实现，默认关闭，可在 [app.config.json](app.config.json) 中配置。关闭时隐藏排行榜及排位模式提示，不初始化排行榜、不发起排行榜请求，上传包不增加排行榜接口或联网权限；七关挑战、动画、道具和个人最高分照常使用。部署、计分规则和权限说明见 [排行榜部署](server/README.md)。

| 关卡 | 步数 | 收集目标 |
| --- | --- | --- |
| 1 | 22 | 红色 12 颗 |
| 2 | 25 | 黄色、绿色各 15 颗 |
| 3 | 26 | 蓝色、紫色各 18 颗 |
| 4 | 26 | 红色、橙色各 20 颗 |
| 5 | 28 | 绿色、蓝色、紫色各 22 颗 |
| 6 | 28 | 红色、黄色、橙色各 25 颗 |
| 7 | 30 | 六种颜色各 20 颗 |

收齐所有目标后解锁下一关；最后一步收齐仍算过关。失败可重玩本关，之前的解锁进度不会丢失。顶部可切换到已解锁关卡（切换会新开该关，不保留多个进行中的棋盘）。第 7 关结束后显示全部通关，可自由重玩。

普通消除、道具爆破、连消都按实际移除的糖果颜色计数；重叠爆炸同一格只计一次。变成新道具、仍留在棋盘上的糖果暂不计入收集，之后真正被消除时再计入。分数保留为成绩展示，不参与过关判定。

关卡目标和步数集中在 `src/levels.ts`，修改这里即可调整难度。社区存档保存当前关卡、已通关数量、颜色计数、棋盘和道具；旧积分模式存档会保留棋盘、道具，从第一关的零收集、满步数开始，历史最高分保留。本地预览仍只保留当前页面内的进度。

## 特殊糖果

每组四个及以上的匹配（包括五连和相交的 T/L 形）随机生成一颗特殊糖果，三种类型等概率。普通三连不会奖励，两组互不相连的三连也不会合并计算。掉落产生的四连同样有奖励。

| 标记 | 道具 | 效果 |
| --- | --- | --- |
| ✹ | 范围爆破 | 清除以自身为中心的 3×3 区域，边缘处只清棋盘内格子 |
| ↔ | 整行消除 | 清除自身所在的整行 |
| ↕ | 整列消除 | 清除自身所在的整列 |

特殊糖果带金色边框和符号。点击即可引爆，也可滑动到相邻格后引爆，主动操作消耗 1 步。被匹配消除或其他道具命中时自动连锁触发，不额外扣步；同一轮每颗道具只触发一次、每格只计分一次。爆炸范围本身不产生额外奖励。

奖励会在匹配位置生成并随糖果下落，新奖励不会在生成的同一轮被炸掉，但后续连消可以触发它。道具随社区存档保存，兼容此前没有道具的旧存档。本地预览仍只在当前页面保留进度。

## 动画验收

- 交换能三连的糖果，观察交换、消除、下落和下一轮连消依次播放。
- 交换不能消除的糖果，应回弹，且不扣步数。
- 动画中连续点击、暂停、切换窗口或重新开始，不应卡住或覆盖新棋盘。
- 收齐本关所有颜色目标后显示胜利彩纸并解锁下一关；步数用尽但目标未完成时显示失败。
- 测试重玩本关、切换已解锁关卡、全部七关通关，以及社区存档恢复；开启系统“减少动效”后仍正常收集、计分。
- 用 375px 左右的手机视口检查棋盘、触摸交换和按钮，无横向滚动。
- 连成四个或五个，检查金色特殊糖果的生成动画；点击后分别验证 3×3、整行、整列效果。
- 用一个道具命中其他道具，检查连锁爆破只扣一步；爆破中暂停或重开应正常结束动画。

运行 `bun test test` 检查规则和动画帧数据，运行 `bun run build` 检查类型并生成上传包。

## 开发与打包

### 排行榜开关

`app.config.json` 控制是否启用排行榜：

```json
{
  "leaderboard": {
    "enabled": false
  }
}
```

当前保持 `false`，直接执行 `bun run build` 即可生成隐藏排行榜的上传包。即使环境中留有 `MINI_APP_API_ORIGIN`，也不会开启排行榜。旧存档中的棋盘、关卡进度和个人最高分仍可使用，未完成的排位按普通游戏继续，不再保留排位提交记录。

以后部署好服务，将 `enabled` 改为 `true`，设置 `MINI_APP_API_ORIGIN` 为真实 HTTPS 服务地址，再重新打包上传；开启但未配置地址时打包会明确报错。配置会随应用版本发布，修改后需重新打包，本地开发建议重启预览服务。

### 1.0.1 动画性能优化

棋盘只更新发生变化的格子和文字；动画使用缓存的棋盘坐标，在窗口或棋盘尺寸变化时重新测量。消除粒子每轮最多 30 个，同一行/列的重复扫光合并，密集连锁最多显示 12 个爆破光效（所有道具仍正常结算）。糖果动画只改变位移、缩放和透明度，避免逐帧改变滤镜或文字颜色。特效层和棋盘限制自身布局、绘制的影响范围。

本地 Chromium、375px 视口、4 倍 CPU 降速下，对相同棋盘每种场景测试 3 次，取中位数：

| 场景 / 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 三道具连锁：DOM 修改次数 | 2834 | 296 |
| 三道具连锁：布局次数 | 33 | 9 |
| 满屏道具压力场景：DOM 修改次数 | 4296 | 601 |
| 满屏道具压力场景：布局次数 | 112 | 14 |
| 满屏道具压力场景：95% 帧间隔 | 33.4 ms | 16.8 ms |

同一输入的最终棋盘、道具、分数和收集数量一致。上述是本地受控测量，不能代替真实社区沙箱或手机性能；压力场景仍偶有慢帧。已额外验证压缩后的上传脚本在暂停、重开、尺寸变化、语言切换和减少动效设置下正常工作。

普通 `build` 会压缩 JS/CSS，不附带 source map；`build:debug` 保留可读代码与源码映射。测试动画性能时优先上传普通构建，以减少加载和开发工具处理源码的开销。

应用图标位于 [branding/app-icon.png](branding/app-icon.png)，在社区应用管理页上传。原图为 1254 × 1254 PNG，生成说明与提示词见 [branding/README.md](branding/README.md)。

需要 Bun 1.4.3+：

```sh
bun install --frozen-lockfile
bun run dev
MINI_APP_ID=社区分配的应用ID MINI_APP_VERSION=1.0.0 bun run build
```

本地预览地址为 `http://127.0.0.1:5194/`，上传 `dist/package/app.zip`。正式应用的 `manifest.json` 中必须使用社区应用页面分配的 ID；示例里的占位 ID只能用于本地构建调试。

游戏会申请 `user.read`、`theme.read`、`storage.read` 和 `storage.write`：用户资料用于展示当前玩家，主题用于颜色与语言，存储用于恢复本局和保存最高分。权限被拒绝或社区不可用时仍可离线游玩。页面隐藏时自动暂停，支持减少动效和窄屏触摸操作。
